# Production acceptance matrix

Every release claim maps to an oracle below. Commands may be refined as the
implementation lands, but a claim cannot be removed merely to make a gate
green.

| Claim | Required oracle |
| --- | --- |
| Identifiers and descriptors reject malformed, duplicate, oversized, and conflicting input | Unit/table tests over public constructors and typed error tags |
| Resolution is insertion-order independent | Property test permuting equivalent descriptor sets |
| Missing, incompatible, ambiguous, self, and cyclic dependencies fail closed | Unit/property tests with exact structured subjects |
| Startup and teardown order respects every selected edge | Graph property test plus lifecycle recording integration test |
| Provision publication is atomic and descriptor/type checked | Failure-injection tests around every validation and commit boundary |
| Initialization/start failure rolls back all completed work | State-machine model tests with injected hook failures, plus hook-unwind tests that convert panics into `plugin.hook-panicked` and still reverse-dispose already initialized plugins; injected-hook tests cover partial multi-plugin rollback, reverse disposal, start rollback, and retained cleanup failures |
| Shutdown is reverse ordered and idempotent | Integration/property tests including cleanup failures and a later dispose hook still running after an earlier cleanup unwind |
| Consumers cannot use supported APIs to resolve undeclared or wrong-cardinality capabilities | Resolver surface review plus runtime negative tests for undeclared access and representative `require`/`optional`/`all` mode mismatches; compile-fail protects scope lifetime escape and `InitializationContext` `'static` escape |
| Root capability access closes at shutdown admission | `RunningApp::capability_from` rejects with `access.application-unavailable` as soon as the application scope enters `Closing`, before cleanup hooks finish; direct handles acquired earlier remain the documented non-revocable residual |
| Tokio tasks are cancelled, drained, failed closed on panic, or reported | Paused-time concurrency tests plus stubborn and panicking task fixtures; forced abort waits for tracked futures to be destroyed before stop returns |
| Warm serverless invocations share only App state | Concurrent unique-scope/request-data test plus long-lived child-retention regression |
| Host runtime requirements fail closed before readiness | Tokio host negotiation test rejects a missing or incompatible versioned HostCapability before plugin initialization |
| Core is runtime/provider independent | Cargo dependency-graph assertion and core compile without Tokio/Serde features |
| Diagnostics and graph export are deterministic | Golden semantic fixtures generated from domain values, not source text; report readers reject an unsupported report schema independently of composition input |
| Public examples remain usable | Doctests, long-lived/serverless examples, and the standalone `fixtures/clean-consumer` typed graph plus direct-call build outside the root workspace |
| Verified-application graph shape is inspectable without startup | `kernox_core::verify_graph_attribution` and `cargo kernox check --verified` reject fewer than three plugins, missing source, and duplicate source packages with the same tags as the testkit |
| A real typed consumer remains responsive under bounded concurrency | `fixtures/clean-consumer --workload` executes 2,048 typed application calls across four threads, validates every result, and enforces p99 <= 5 ms plus max <= 100 ms |
| A standalone typed consumer survives a warm host lifecycle | `fixtures/clean-consumer --serverless` rejects capacity while occupied, surfaces handler failure without leaking an invocation, observes fresh child scopes, shuts down cleanly, and rejects post-shutdown admission |
| A standalone typed consumer uses cardinality contracts | `fixtures/clean-consumer --fanout` injects two required providers with `all`, observes an absent `ZeroOrOne` capability with `optional`, dispatches in stable provider order, and shuts down cleanly |
| Repository CI uses approved execution authority | Every workflow job uses one static Sylphx Platform self-hosted profile; Linux uses `sylphx-linux-standard`, the macOS portability lane uses `[self-hosted, sylphx, macos, standard]`, and Windows remains open until Platform publishes an approved profile; hosted or invented runner labels are forbidden |
| Trusted native boundary is represented honestly | Security negative tests and documentation review; no sandbox claim |
| Untrusted graph input is bounded | Fuzz/property tests for parsing, size limits, and pathological graphs |
| Direct runtime calls do not traverse the graph | API shape review and benchmark against a direct trait-call baseline |
| Graph construction remains bounded | Criterion distributions for 10, 100, and 1,000 plugins with sparse/dense valid edges |
| Steady-state overhead is commercially negligible | Representative benchmark delta no greater than 2% versus direct composition, or redesign with recorded evidence |
| Release is reproducible and supportable | Locked build, fmt, clippy, test, docs, audit, license/source policy, semver, package dry-run, and registry readback |

Current benchmark evidence is recorded in [`docs/performance.md`](../performance.md).
It is revision-specific and does not replace the scheduled regression lane.

## Verification lanes

`cargo run -p xtask -- verify` is the local and presubmit commit build. It owns
formatting, clippy, tests, docs, dependency policy, and package checks that are
fast and deterministic.

Fuzzing, broad mutation testing, extended concurrency, performance
distributions, and semantic-version comparison run on scheduled or
release-triggered lanes unless the changed surface makes them admission
critical. No coverage-percentage threshold is a release proxy.

## Release blockers

- Any unresolved requirement in `docs/prd.md`.
- Any public API item without contract documentation.
- Any `unsafe` block in project-owned Rust source without a separately accepted
  security/performance ADR; the initial policy is `forbid`.
- Any dependency advisory, incompatible license/source, unpinned release input,
  or committed secret.
- Any benchmark regression beyond budget without a measured accepted tradeoff.
- Any example that requires Sylphx-only infrastructure to demonstrate Kernox.
